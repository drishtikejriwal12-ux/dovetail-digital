Case study · UX/UI Design · Wellness · Concept

Tidewell

A booking experience for a seaside studio, designed so the hardest step, choosing a session, feels like the easiest.

Type
UX/UI design
Timeline
8 weeks (concept)
Role
Research, journeys, interface, prototype
Shipped
Four-step mobile booking flow and prototype

This is a fictional concept project. There is no real client, and nothing here describes real results.

The challenge

People arriving at a wellness studio's site are often tired or unsure what they need. A long list of class types and a calendar grid asks them to make several decisions at once, and many give up.

The approach

We reduced booking to one decision per screen, wrote every label in plain language, and made touch targets generous. The calm look is a result of fewer choices, not extra decoration.

The process

Four steps, one thread.

  1. 01

    Discover

    We mapped how someone goes from "I should do something for myself" to a confirmed booking, and marked every point where a person might stop. Most drop-off risk sat at the moment of choosing between session types.

    Output: journey map and problem statement

  2. 02

    Define

    The principle became "one decision per screen". Session types were rewritten around how a person feels, not how the studio schedules.

    Output: flow diagram and content model

  3. 03

    Design

    We drew the flow on paper first, then built high-fidelity screens at phone width. Contrast, touch size and focus order were set before colour.

    Output: interface design and component set

  4. 04

    Deliver

    A clickable prototype of all four steps, with notes on each state: empty, loading, error and success.

    Output: prototype and handoff notes

What shipped

Screens shipped

The four-step booking flow, in order.

What we took from it

Fewer choices, more bookings (to test)

The flow is built to be measured: the next step would be testing completion against the old calendar view.

Words are interface

Renaming session types did as much work as any layout change.

Design the quiet states

Confirmation and error screens are where trust is built.
